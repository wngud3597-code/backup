배틀싸피 v1.3 팀 코드 사용 안내

권장 파일: strategy_6_improved.py
세 탱크 모두 이 파일 하나를 사용합니다. 외부 패키지와 보조 파일은 필요 없습니다.
게임의 Python 코드 선택 화면에서 이 .py 파일을 등록하고 실행하세요.
기존 attack_bot.py는 공격 역할만 담당하는 별도 단일 파일입니다.
표시 이름을 바꾸려면 코드 위쪽 NICKNAME 값만 수정하세요.

기본 팀 배치
- 아군 포탑 H에 가까운 두 시작 탱크: 수비1, 수비2.
- 나머지 탱크: 상대 포탑 X 공격.
- A팀/B팀을 지정하지 않습니다. 수신한 M/H/X와 배포본의 시작 배치로 판별합니다.
- 표준 16x16 배틀맵에서는 자기 시작 구역으로 탱크 번호를 고정해 역할 중복을 피합니다.
- 공격수는 이동 중 직선 사거리 3칸 안에 적 탱크가 들어오면 교전합니다.
- 즉시 포탑을 파괴할 수 있는 사격은 최우선입니다.
- 수비수는 서로 다른 두 칸을 왕복하며 사거리 안의 침입 탱크를 요격합니다.
- 아군 탱크, H, 바위 R, 보급시설 F가 포탄 앞을 가리면 발사하지 않습니다.
- 필요한 나무 제거, 탄종별 잔탄, 일반30/메가70, 누적 모래 피해를 계산합니다.
- 배포 v1.3 암호 규칙에 맞춰 필요할 때 보급받습니다. 메가10개에서 보급하지 않습니다.
- 공격수가 파괴되면 남은 수비수 중 한 대가 공격을 승계하되 본진 침입 대응을 우선합니다.

명령줄 실행 (게임 서버가 먼저 대기 중이어야 합니다)
python strategy_6_improved.py
python strategy_6_improved.py --nickname MyName
수동 역할: --role attack / --role defend1 / --role defend2
게임에서 별도 인수를 주지 않으면 --role auto가 적용됩니다.
이미 지정한 수비 코드 두 개를 유지하려면 나머지 한 탱크에 attack_bot.py를 등록할 수도 있습니다.

strategy_6.py 비교에서 확인한 사항
팀원의 쌍 초소 순찰과 1공격2수비 구조를 채택했습니다.
정적 상대를 둔 실제 배포 지형 24조건에서는 원본과 새 공격 엔진이 모두24회 포탑을 파괴했고,
총 행동 수는 원본559/새556으로 일반적인 경로 성능은 비슷했습니다.
원본은 사거리 안 적 탱크를 무시하는 기본 설정, 빈 일반탄 발사, 낮은 HP에서 치명적 모래 경로,
HP30 적에게 메가탄 사용, 분할 수신 오인 사례를 재현했습니다. 개선본은 이를 보완합니다.
수비의 보급과 역할 승계는 움직이는 상대 모델에서도 비교하여 본진 방어를 우선합니다.

검증 범위
배포 ZIP의 Python3.9.13으로 컴파일, 접속 없는 import, --help 실행을 확인했습니다.
표준 라이브러리만 쓰는 단일 파일이며 한글/공백이 있는 독립 폴더에서도 실행했습니다.
동일 팀 파일을 실제 번들 Python 프로세스3개로 동시에 띄워 A/B 각각의 모의 TCP 대전을
초기 INIT부터 분할된 상태 수신, 반복 명령, 실제 종료신호까지 확인했습니다.
실제 배포 지형4개, 양팀, 순찰, 탄약, 아군/바위 사선 차단 등을 독립 모델로 검사했습니다.
검증 스크립트와 상세 자료는 .inspection/verification 에 있습니다.

확인 범위와 예외 상황
실제 Unity 게임 GUI에서 대전을 직접 실행한 검증과 실제 대회 승률 측정은 하지 않았습니다.
엔진은 상태 끝 개행/길이를 보내지 않으므로 로컬 TCP 수신은 형식 검사와10ms 추가수신 확인을
사용합니다. 임의로 오래 지연되는 최종 TCP 조각까지 완벽하게 구별할 수는 없습니다.
이동/사격/보급이 모두 불가능한 예외적인 갇힘에서는 연결을 끊는 대신 S를 반환합니다.
S는 배틀에서 옐로카드이므로 정상 이동이나 사격이 가능한 때는 사용하지 않습니다.
