팀전 방어 전용 전략 — 방어2대 + 별도 공격1대

팀 구성
방어 탱크 A: [지역반_이름], 실제 Player 번호 [입력]
방어 탱크 B: [지역반_이름], 실제 Player 번호 [입력]
공격 탱크: [지역반_이름], 실제 Player 번호 [입력], 공격 코드는 별도 준비
이 묶음에는 방어 코드2개만 있습니다. Defender1/2는 구분용이며 제출 전에 실제
Player번호_지역반_이름.py로 파일명을 바꾸고 NICKNAME도 기입합니다.

방어 동작
1. 자기 식별은 M. 각 방어 봇은 첫 유효 수신의 자기 위치를 방어 기준점으로 한 번만 저장합니다.
   두 봇 모두 방어합니다. 다른 아군이 더 가깝다는 이유로 공격 역할로 바뀌지 않습니다.
2. 기준점에서 맨해튼2칸 이내의 G 연속2~3칸을 찾아 짧게 왕복합니다.
   rows는 행 값을 바꾸는 상하 이동, cols는 열 값을 바꾸는 좌우 이동입니다.
   가능한 축과 사선을 평가해 하나를 택하고 끝점·진행 방향을 유지합니다.
   모래는 반복 순찰에서 제외하고 아군/벽/금지영역도 통과하지 않습니다.
3. 실제 첫 사격 대상으로 보이는 사거리3칸의 적 탱크를 추적 대상으로 잡습니다.
   4칸 밖·대각선·벽/아군 뒤의 적을 거리만 보고 추적하지 않습니다.
4. 적이 움직이면 사격 가능한 위치를 다시 찾아 따라갑니다. 내 탱크의 이동 한계는
   처음 기준점으로부터 맨해튼3칸입니다. 경로 중간점/회피/계산중단 대체 명령도 이 범위를 지킵니다.
   표적이 아직 사거리 밖이면 사격 위치로 이동하고, 사선이 열리면 다시 발사합니다.
5. 표적 HP0·관측 누락·탄약소진 또는 추격 범위 안에서 사격할 위치가 없으면 추적을 해제합니다.
   기준점 주변 순찰 구역으로 돌아갑니다. 기준점이 아군에게 막혀 있으면 접근 가능한 구간으로 복귀합니다.
   새 위치를 기준점으로 삼지 않으므로 장기 추격으로 방어 구역이 이동하지 않습니다.
6. 일반탄30/메가탄70, 두 탄종 사거리3. 실제 HP·탄약으로 필요한 발수를 계산합니다.
   낮은 HP에 메가탄을 낭비하지 않으며 공격 후 실제 수신 상태로 재계획합니다。
   즉시 포탑 파괴 또는 확인된 두 번째 적 탱크 격파는 모든 이동보다 우선합니다.
7. 아군 한 대 사망을 관측한 경우 자기 추가 격파 위험을 크게 평가합니다.
   적을 처치한 뒤 뒤쪽 적에게 사선이 열리는 경우도 고려합니다. 적 탄약·차례는 확정하지 않습니다.
8. S 대기나 방향만 출력하는 명령은 사용하지 않습니다. 전송 직전에 이동/탄약/사선을 다시 검사합니다.
   방어 범위 내에서 합법적인 행동을 찾지 못하면 이를 명시하며 안전한 행동이 항상 있다고 가정하지 않습니다.

기본 전략 설정
patrol.mode=always, radius=2, chase_radius=3, max_span=3.
mode=off여도 방어 범위 제한은 유지되며 장거리 공격 봇으로 바뀌지 않습니다.
이 반경들은 봇의 전략 설정입니다. 공식 H3×3 금지구역 좌표를 뜻하지 않습니다.
각 방어 탱크는 처음 배치된 방어 위치 주변을 지킵니다. 두 탱크의 시작 위치를 서로 다른 방어 통로로
배치하면 간섭을 줄일 수 있습니다. 동일 지도 정보로 아군 점유를 검사하며 별도 통신은 하지 않습니다.

남은 확인
- H금지영역 좌표 미확인: H가 있고 전체영역 미설정이면 이동 억제. 임의 centered3×3 가정 없음.
- 수신 마지막개행 미확인: transport.framing=null로 라이브 접속 전 차단.
- 현재 Caesar간격 미확인: supply.shift=null로 보급 비활성. 예제+9를 모든 경기에 가정하지 않음.
- 보급량/카드 누적/아군피격/행동순서/팀전응답제한/나무 명중횟수는 추가 확인 필요.
- 사망은 명시적HP0만 집계. 누락을 두 번째 격파 승리로 추정하지 않음.
- 100턴 판정은 피해→거리→후공. 전체턴/피해기준/거리정의가 없으므로 완전한 후반 최적화는 미완료.
- 순찰/추격 검증은 저장상태와 합성 지도에서 수행했으며 실제 경기 승률은 측정하지 않았습니다.

실행/제출
각 방어 Python 파일은 표준라이브러리만 사용하며 RULES를 내장합니다.
설정 확정 후 python build_templates.py --rules rules.team.json으로 두 방어 후보를 다시 만듭니다.
세 번째 공격 코드는 별도로 준비하고 실제 Player순서와 팀원명단을 맞춰 최종 제출 ZIP을 구성합니다.
현재 defender_candidates.zip은 방어2대 후보만 담으며 외부에 제출하지 않았습니다.
