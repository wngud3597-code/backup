# Movie Lab 프로젝트 작업 규칙

사용자가 앞서 전달한 프로젝트 규칙을 저장한 문서다. 최신 사용자 지시가 이 문서보다 우선한다.

- 실제 프로젝트는 이 폴더다. 실습 ZIP 비교나 전체 요구사항 분석을 반복하지 않는다.
- 앱 코드는 프로젝트 상대 경로나 환경변수 설정을 사용한다. 개인 PC 절대 경로를 고정하지 않는다.
- 기존 실습 파일, requirements.txt, 영화 선택, 영화별 질문 기록과 답변별 당시 출처를 보존한다.
- 대화는 threads_by_movie[movie_id] 한 곳에 저장한다. assistant 메시지에 answer_id/content/sources를 함께 저장하고 출처를 중복 보관하지 않는다.
- 일반 rerun과 영화 전환에서 기록을 보존한다. 영구 대화 저장은 현재 범위가 아니다.
- 기존 GMS 주소와 GMS_KEY, python-dotenv 방식 및 GMS_CHAT_MODEL 설정을 유지한다. gpt-4o-mini는 현재 프로젝트 기본값이며 수업에서 강제한 유일한 모델이 아니다. 모델 비교는 답변 신뢰성 수정과 분리하며 사용자가 요청하지 않은 채팅 연결 재검사나 다른 모델 호출을 하지 않는다.
- 키와 .env 내용을 도구 출력·로그·코드·ZIP에 포함하지 않는다. 승인된 클라이언트 실행에서만 환경변수로 읽어 전달한다. 예외 본문·헤더·트레이스백을 그대로 출력하지 않는다.
- 메타데이터, 작품 속 묘사, 현실 사실, 사용자 주장, 서비스 해석을 구분한다. 실제 인용 출처만 표시하고 답변의 근거 번호는 해당 답변의 출처 목록에만 대응한다.
- 근거 부족을 거짓으로 판정하지 않는다. 불필요한 결말·줄거리를 추가하지 않는다. Mock 문서·테스트 답변을 실제 결과처럼 노출하지 않는다.
- PDF 버전은 기준 환경으로 참고하며 현재 설치 조합을 우선 재사용한다. 버전 표만을 이유로 강제 업그레이드·다운그레이드하지 않는다. 기능에 필요한 변경만 기존 가상환경에서 호환성·설치 전 resolver·설치 후 pip check로 확인하고 실제 버전과 이유를 기록한다. 전역 설치·임의 최신 교체를 하지 않는다.
- 임베딩은 채팅과 별도로 모델·실제 차원을 검증한다. 문서와 질문은 같은 임베딩 설정을 사용한다. 소량 검증 후 전체 메타데이터를 색인한다.
- 메타데이터와 외부 문서는 컬렉션을 분리한다. 안정적인 ID·내용 해시·설정 버전으로 중복과 불필요한 재임베딩을 방지한다. 저장 확인된 항목으로 재개하며 부분 실패를 전체 완료로 기록하지 않는다.
- 네 번째 구현에서 완성한 조건·본문 캐시·Retry-After 수정, LangGraph retrieve → generate, 답변별 인용 범위·원문 검사와 작품·현실 배경 확인 모드를 보존한다. 현재 문서 정리에서 이 기능을 재구현하거나 전체 영화 외부 문서 일괄 수집·별도 프론트엔드·MMR·추가 모델 비교를 하지 않는다.
- 질문별 선별 캐시와 문서별 최신 본문 캐시는 분리한다. 과거 질문 재방문으로 최신 활성 문서를 구본문으로 덮어쓰지 않는다. 과거 답변의 출처 스냅샷은 갱신하지 않는다. Retry-After를 줄여 조기 재요청하지 않으며 대기 한도를 넘으면 대체 경로로 전환한다.
- 근거 부족 판정은 인용을 강제하지 않으며 관련 없는 구절로 보류 안내를 채우지 않는다. 같은 답변의 한 출처에 여러 실제 구절을 허용하고 기존 quote·출처 번호와 과거 스냅샷을 보존한다.
- 완료된 감독 필드 보완의 저장 실패 재생·실제 호출 기록을 보존한다. 원질문의 명확한 긍정 감독 명제·정확한 전체 이름·선택 ID·실제 메타데이터 구절이 모두 대응할 때만 근거 부족 항목을 검토용 제안으로 구성하고 기존 항목별 검토를 거친다. 이름 문자열 레지스트리를 전세계 인물 ID나 별칭 사전으로 취급하지 않는다. 부분 이름·표기 동일성이 불확실한 경우·부정/조건·다른 역할·누락 근거에는 적용하지 않는다.
- RAG 기능 개발은 종료했다. 최신 사용자 지시의 UI 마무리 범위는 2026-10-22 16:30 KST에 확정했다: 검색 중심 첫 화면·입력만 채우는 검색 예시와 영화별 추천 질문·간결한 메타데이터·접힌 운영/상세 설정·읽기 쉬운 인용·공식 테마·좁은 화면과 상태 보존 검사다. 17시 이후에는 이 범위의 검증·수정만 하며 내일은 사용 검증·수정·제출 정리를 진행한다. 별도 API/패키지/프론트엔드·모델/색인 실험·백엔드 판정 계약 변경은 포함하지 않는다.
- 생성 gpt-4o-mini·검토 gpt-5.4-mini와 기존 GMS_CHAT_MODEL 복귀 경로를 유지한다. 완료된 전체 분석·모델 비교·두 질문을 반복하지 않는다. 이번 자동 화면 확인은 저장 결과 재생/대체 응답임을 명시하며 새 실제 채팅·임베딩·외부 데이터 요청은 0회다. SDK 자동 재시도는 0이며 검토 장애를 낮은 모델의 자동 수락으로 대체하지 않는다.
- 정상 앱은 기존 scripts/run_review_profile.ps1을 우선 사용하고 중복 서버를 만들지 않는다. 실행 정책이 제한되면 전역 정책을 바꾸지 않고 프로세스 환경변수로 같은 역할 프로필을 실행한다. 저장 결과 재생과 정상 앱을 구분한다. Codex가 대신 질문을 제출하거나 자동 시연하지 않으며 사용자가 정상 앱을 직접 이용하는 API 호출은 허용한다. 강제 자료 갱신·재색인·별도 벤치마크는 실행하지 않는다.
- docs/USER_ACCEPTANCE.md의 실제 결과는 모두 미실시로 시작한다. 사용자의 결과와 증거를 받은 뒤에만 반영한다. 과거 Codex 검사·저장 재생을 사용자/동료 점검 완료로 바꾸지 않는다. 제출을 막는 오류와 명확한 요구사항 결함만 수정하고 해당 검사만 수행한다. API 502의 실패 단계와 저장 근거 대체 여부를 나누어 기록한다. KOBIS는 키가 없으면 선택 기능·실제 연결 미확인으로 유지하며 TTL0·명시 조회·독립 표시·외부 저장 금지를 보존한다.
- 최종 제출 ZIP 준비는 최신 사용자 지시로 허용됐다. 이전 단계의 새 ZIP 금지는 이 마무리에 적용하지 않는다. 사용자 직접 결과를 반영한 뒤 현재 폴더의 최신 코드·실행 프로필·문서·선별 증거로 새 제출 ZIP을 구성하고 이전 기준본/검토 ZIP은 보존한다. 키·.env·가상환경·브라우저 프로필·불필요한 저장소·권한이 확인되지 않은 원본 데이터는 제외한다. 파일명과 제출 정보는 PDF의 자리표시자/예시를 실제 신상이나 마감으로 추정하지 않는다. 압축 무결성·필수 파일·문서 상대 링크·제외 항목을 확인하며 외부 업로드·push·실제 제출은 하지 않는다.
- 특화 검토는 코드의 항목 ID별로 사용자 명제와 원문 관계·서비스 이유 지지를 반환받아 판정과 대조한다. 누락·중복·형식·관계 불일치는 검토 보류이며 사실의 거짓이나 근거 부족으로 바꾸지 않는다. 독립적으로 통과한 항목과 당시 출처는 보존한다. 일반 답변의 검토 계약은 유지한다.
- 수업 기준 2일차 17시 이후에는 새 기능을 시작하지 않는다. 필수 기능을 먼저 완성한다.
- 실제 실행과 오프라인 테스트를 구분해 결과·명령·미확인 사항을 기록한다. 의미 검색만으로 F2011 조건 탐색 전체를 완료 처리하지 않는다. 확인하지 않은 배점·가격·성능·호환성을 만들지 않는다.
- 검토 ZIP은 허용 파일만 포함한다. .env, 키, 가상환경, Chroma 저장소, 전체 배포 데이터는 제외하고 외부 업로드·게시는 하지 않는다.
