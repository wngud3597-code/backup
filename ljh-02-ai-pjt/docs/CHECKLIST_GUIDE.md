**남은 제출 검증도 있다.** 5번은 청킹 설정 변경 후 실제 재색인 전후 비교, 6번은 Top-k만 바꾼 동일 질문 근거 목록 비교가 미실시다. 두 기능의 구현/설정이 존재한다는 것과 해당 비교 실험을 했다는 것은 다르다. 실제 동료 점검, 최종 증빙 대조·제출물 구성도 남아 있다. 이를 전체 미구현으로 취급하거나 반대로 전부 통과로 바꾸지 않는다.

기존 검증 증거는 위 표와 통합 요구사항표에서 인정한다. 공식 셀프/상호 결과는 실제 확인자가 확인한 범위를 기록한다. **아직 전달받지 않은 사용자의 점검 결과나 동료의 이름·평가를 대신 작성하지 않는다.**

**작성은 `.xlsx`로 진행하고 이 형식을 유지하는 편이 적절하다.** 결과 드롭다운과 자동 집계 수식이 있다. CSV·TXT로 저장하면 양식이 보존되지 않는다. PDF 제출을 별도로 요구받으면 **점검을 마친 엑셀을 PDF로 내보내고** 페이지와 누락을 확인한다. 아직 완성 PDF를 만들거나 제출하지 않았다.

수업 양식의 일정은 **3일차 셀프 15:30~16:30, 상호 16:30~17:30**이다. 이는 점검 일정이며 별도 LMS 최종 제출 마감을 확정하는 근거가 아니다.

## 작성 순서

1. 엑셀에서 `체크리스트` 시트를 연다. 상단 연한 노란 칸의 **앱 작성자·점검자·실제 점검 일시**를 적는다. 셀프의 점검자는 본인, 상호의 점검자는 실제 동료다. 이름과 일시는 추정하지 않아 비워두었다.
2. 각 항목을 실제 확인한 뒤 **G열 결과 / H열 증빙 파일명 / I열 비고**를 작성한다. 항목 번호는 C열의 1~27이며 엑셀 행 번호와 다르다. 기존 확인 항목·방법과 자동 집계 수식은 고치지 않는다.
3. `통과`는 직접 기대 결과를 확인한 항목만, `실패`는 실행 결과가 다른 항목에 쓴다. 실행하지 못하면 `미확인`과 이유를 남긴다. 선택하지 않은 심화·적용되지 않는 도메인에는 `해당없음`과 이유를 적는다. 공식 결과 목록에는 `미실시`가 없으므로, 실행하지 않았다는 뜻은 **결과 `미확인` / 비고 `직접 점검 미실시`**로 옮긴다.
4. 셀프 H열의 `참고:`는 **과거 Codex 자료**다. 이를 본인의 캡처처럼 쓰지 않는다. 실제 점검 후 본인 증거 파일명으로 바꾸고 제출물에 그 파일도 함께 넣는다. 예를 들어 `08_답변_근거.png`는 권장 이름일 뿐 현재 존재하는 증거가 아니다. 아래 표에서 참고 파일의 전체 경로를 확인할 수 있다.
5. 상호는 실제 점검자에게 사본을 전달해 결과와 **잘한 것 하나·개선할 것 하나**를 직접 받아 적는다. 현재 피드백은 미작성이다. 다른 교육생을 점검한 사본과 내 앱을 점검받은 사본은 앱 작성자·점검자로 구분하고, 수업의 주고받기 안내를 따른다.
6. 하단 집계와 첨부 파일을 대조한다. 실패·미확인에 이유를 적고 최종 제출 폴더의 `submission/checklists/`에 실제 작성본을 포함한다. 양식 준비와 점검 완료·제출 완료는 다른 상태다.

## 이번 파일 확인 범위

[파일 검사 기록](../artifacts/checklist_preparation/validation.json)에 원본/작성본 SHA-256과 집계가 있다. 원본 두 파일을 바이트 그대로 보존했고, 작성본의 CRC·XML·수식·드롭다운·스타일·병합·인쇄 설정과 참고 파일 존재를 확인했다. 수정은 노란 입력 칸과 집계 수식의 **계산된 캐시 값**뿐이며 수식 자체는 유지했다. 실제 Excel에서 열기·인쇄 렌더링은 미확인이다. 열었을 때 두 시트와 결과 드롭다운·집계를 한 번 확인한다.

앱 코드·환경·기존 증거·이전 ZIP은 변경하지 않았다. 제출용 전체 ZIP과 작성 완료 PDF는 아직 만들지 않았으며 외부 업로드·제출을 하지 않았다.
