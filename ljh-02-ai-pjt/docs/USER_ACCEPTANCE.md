# 사용자 직접 점검표

이 문서는 UI 마무리를 반영한 앱을 **사용자가 직접** 확인하고 결과를 적는 양식이다. 작성만으로 점검을 실시한 것이 아니다. 아래의 실제 결과와 상태는 모두 **미실시**, 증거 경로와 확인자·시각은 모두 **미기록**으로 시작한다. Codex의 과거 실제 호출·브라우저 검사·자동 테스트·저장 결과 재생은 사용자 점검 완료를 대신하지 않는다.

접속 주소: **http://127.0.0.1:8501**. 원본 `app.py`의 정상 앱을 준비하고 무질문 health `200/ok`를 확인했다. 관찰·저장 결과 재생 앱이 아니다. Codex는 질문을 전송하지 않았다. 화면에 ‘저장 결과 재생’ 안내가 있으면 새 질문을 점검하는 정상 세션으로 사용하지 않는다.

## 시작 전에

- 같은 브라우저 탭과 같은 앱 세션을 유지한다. **완전 새로고침(F5/Ctrl+R), 탭 닫기, 새 탭 이동, 서버 재시작, 대화 지우기, 자료 강제 갱신을 피한다.** 이 앱은 세션 종료 후 영구 대화 보존을 약속하지 않는다.
- A는 **인터스텔라(2014), 영화 ID 157336**, B는 **더 문(2023), 영화 ID 753091**로 정한다. 제목만 보지 말고 선택 카드의 연도·감독·ID를 함께 확인한다.
- 선택 카드에서는 제목·연도·감독을, **영화 상세 정보**를 펼쳐 영화 ID·원래 평점·평가 수를 확인한다. 줄거리는 별도로 접혀 있으며 원할 때만 펼친다.
- 현재 준비된 프로필은 생성 `gpt-4o-mini`, 검토 `gpt-5.4-mini`다. 점검 중 모델·설정·패키지·색인을 바꾸지 않는다. 원문에 감독/상영 시간 정보가 있는지와 답변의 주장을 직접 대조한다.
- ‘고급 설정 · 자료 미리 준비’ → ‘자료 경로와 갱신 설정’에서 ‘자료 사용 방식’을 **제공 스냅샷**으로 선택하고, **‘성공 캐시를 갱신하고 원문을 다시 확인’은 체크 해제**한다. 스냅샷 ZIP 경로는 담당자가 연결한 기존 값을 유지한다. 설정 확인만 하고 별도의 자료 준비 버튼은 누르지 않는다. 기존 준비 캐시를 우선 사용하며 강제 수집·갱신을 시작하지 않는다.
- 아래 질문은 **입력 예시일 뿐 아직 전송하지 않았다.** 사용자가 실시하기로 한 항목에서 한 번만 전송한다. 오류나 기대 미달 결과를 먼저 기록하며, 성공할 때까지 같은 질문을 재전송하지 않는다. ‘재답변’도 새 요청이므로 화면 확인용으로 누르지 않는다.
- 각 행은 독립해서 판정한다. `통과`는 절차를 직접 실시하고 기대 결과를 관측했을 때만, `실패`는 관측 결과가 기대와 다를 때 적는다. 실시하지 않았거나 필수 증거를 확보하지 못한 행은 `미실시`로 두고 이유를 실제 결과에 적는다. 하지 않은 항목을 통과로 바꾸지 않는다.
- 증거는 해당 행의 실제 관측에만 연결한다. 키·.env 내용·인증 URL·원시 헤더/예외를 복사하지 않는다. KOBIS는 실제 수치 표나 응답 본문을 파일·화면 증거로 저장하지 않고, 날짜·상태·행수·필드 확인 여부·호출 횟수만 적는다.

## 오류·부분 성공을 적는 방법

한 요청에 실패와 대체 성공이 함께 있으면 UA-13과 UA-14를 함께 작성한다. 실제 결과에는 `실패 단계 / 안전한 오류 분류·코드 / 시도 횟수`와 `대체 근거의 종류 / 최종 답변 또는 보류 / 인용 대응`을 나누어 적는다. 예시는 기입 형식일 뿐 실제 점검 결과가 아니다. 실패 단계가 보이지 않으면 추정하지 않고 미확인이라고 적는다.

기대와 다른 답변·없는 인용·영화 혼동·중복이 보이면 그 상태를 먼저 보존한다. 같은 질문을 성공할 때까지 다시 보내거나, 코드를 고친 뒤 과거 결과를 덮어쓰지 않는다. 이번 단계는 기능 추가·재색인·모델 비교가 아닌 사용자 점검과 남은 결과 기록이다.
