# 영화 탐색 업그레이드 계획: 조건에 맞는 ID 안에서 의미 검색

> 지난 준비 단계의 설계를 보존한 문서다. 실제 구현·4회 임베딩 A/B·조건 준수/순위·남은 한계는 [최신 선필터 보고서](../artifacts/review_upgrade/discovery/implementation_report.md)를 따른다. 아래 미구현·미실행 표시는 계획 당시 상태다.

이 문서는 **설계와 검증 계획**이다. 업그레이드를 구현하거나 새 의미 검색·임베딩·모델 호출·회귀 테스트를 실행한 결과가 아니다. 2026-10-22에 현재 코드, 설치된 Chroma 소스, 로컬 영화 메타데이터를 읽고 작은 오프라인 필드 통계와 기존 파서의 해석만 확인했다. 제품 코드·테스트·의존성·저장소·기존 문서는 변경하지 않았다. 실제 실행의 기존 확인 범위는 [통합 요구사항 대조표](REQUIREMENTS.md)를 따른다.

## 1. 바꿀 문제와 유지할 것

현재 `movie_lab/services.py::search_catalog`는 조건을 파싱한 다음, 정확한 제목과 미지원 조건을 먼저 처리한다. 그 외에는 `MetadataIndex.search`로 **전체 메타데이터 컬렉션에서 의미 Top-3**를 얻는다. `discover_movies`는 별도로 전체 영화의 키워드 점수를 구하고, `_matches`로 명시 조건을 적용한 뒤 의미 검색 순위를 더해 최종 최대 10건을 반환한다.

따라서 현재도 명시 조건을 위반한 영화가 최종 결과로 확정되도록 설계된 것은 아니다. 개선할 지점은 **의미 검색의 3개 자리를 조건 불일치 영화가 먼저 차지할 수 있다는 것**이다. 반대로 최종 결과는 키워드 후보도 포함하므로 의미 Top-3와 최종 영화 ID 목록이 서로 다르다는 사실 자체는 오류가 아니다.

제안은 같은 파서로 확인한 조건에 맞는 영화 ID 집합을 먼저 만들고, 그 집합 안에서만 의미 Top-3를 구하는 것이다. Top-k 확대, 예제별 분기, 새 검색 서버·재순위화 모델·의존성 추가는 하지 않는다. 964개 문서의 본문·벡터·ID·임베딩 설정은 유지하며 재임베딩하지 않는다. 영화 선택, 영화별 기록, 답변별 당시 출처, 외부 문서 준비와 답변 생성 계약도 변경 범위 밖이다.

### 설치된 API의 지원 범위

가상환경의 `chromadb`는 **1.5.9**다. 설치 소스 `venv/Lib/site-packages/chromadb/api/models/Collection.py::Collection.query`에는 `ids`와 `where` 인자가 실제 정의되어 있다. 해당 docstring은 `ids`를 검색 대상 ID 부분집합으로 설명한다. `chromadb/api/types.py::validate_where`에는 `$in`/`$nin` 검사도 있다. 이는 **로컬 설치 소스를 읽어 확인한 API 계약**이며, 이번 작업에서 실제 필터 질의를 실행한 것은 아니다. 배포 환경이나 다른 버전까지 검증한 것으로 확대하지 않는다.

권장은 영화 로더의 실제 필드로 만든 적격 ID를 `meta:{movie_id}` 형식으로 변환해 `query`의 ID 부분집합으로 전달하는 안이다. 대안은 이미 저장된 `movie_id` 필드의 `$in` 조건이다. 후자를 선택해도 필드별 조건 번역 대신 동일한 적격 ID 목록을 사용한다. 기존 컬렉션의 스키마 변경과 재색인은 필요하지 않다. 구현 시작 시 설치 API에서 소수 로컬 벡터로 ID 제한 동작을 검증하고, 두 방법을 조용히 혼용하지 않는다.

## 3. 제안 흐름과 실패 계약

기호는 전체 카탈로그 ID 집합 `M`, 명시 조건을 확인한 적격 ID 집합 `C`, 의미 검색 결과 `S`, 화면의 최종 결과 `R`이다.

1. 현재와 같은 제목 우선 규칙으로 질문을 파싱한다. 미지원 조건이 하나라도 있으면 결과를 확정하지 않고 그 이유를 반환한다. 긍정 수치가 함께 파싱되었더라도 수치 부정을 무시하고 진행하지 않는다.
2. 지원 조건을 실제 `Movie` 필드와 대조해 `C`를 만든다. 조건에 필요한 필드가 누락된 영화는 ‘불충족 확인’과 구분해 ‘검증 불가’에 센다. 명시 조건이 없는 질문의 `C`는 `M`이다.
3. 제목/원제의 정확한 일치는 동명 작품을 모두 남기고, 함께 지정한 연도 등 추가 조건을 적용한다. 이 경로는 현재처럼 임베딩 없이 반환한다. 숫자 제목을 개봉 연도로 재해석하지 않는다.
4. `C`가 비면 의미 검색을 호출하지 않는다. 모든 관련 필드를 확인할 수 있고 조건을 충족하는 기록이 없으면 ‘현재 데이터에 조건 일치 결과 없음’이다. 필요한 필드가 없는 기록은 별도로 안내하며, 세계 전체에 해당 영화가 없다는 뜻으로 쓰지 않는다. 미지원 조건은 이 상태와 합치지 않는다.
5. 다른 질문은 현재와 동일한 전처리 문장·모델·1536차원 벡터·의미 `k=3`으로 `C` 안에서 검색한다. 결과 수는 저장 확인된 적격 문서 수와 3 중 작은 값이다. 빈 ID 배열을 전달해 백엔드가 전체 검색으로 해석할 위험을 만들지 않고 4번에서 종료한다.
6. 의미 검색의 `document_id`가 `meta:{movie_id}`와 대응하고, 반환 ID가 현재 카탈로그와 `C` 모두에 속하는지 검사한다. 후보 레코드가 누락·오래됨·불일치이면 그 사실을 보고한다. 검색 실패를 조건 없는 전체 검색으로 대체하지 않는다.
7. 기존 키워드·의미 결합을 적용하되 최종 후보는 `C`에서만 고른다. 첫 A/B 비교에서는 키워드의 문서 빈도·정규화 계산 범위를 현재와 동일하게 유지한다. `C`만으로 키워드 통계를 다시 산출하는 변경은 순위 산식의 별도 변경이므로 이번 비교에 섞지 않는다.
8. 화면 직전에 같은 조건을 다시 검증하고, 제목·연도·감독·조건 근거와 안정적인 영화 ID를 반환한다. 의미·줄거리 유사성은 후보 정렬 이유이며 검증된 명시 조건으로 표시하지 않는다. 선택하면 기존 영화 ID의 기록으로 이동한다.

지원 조건만 있는 질문의 임베딩 생략 같은 호출 최적화는 첫 A/B의 조건이 바뀌므로 별도 후속 항목이다. 우선 제목·미지원·빈 적격 집합에 대해서만 무호출 계약을 확실히 한다.

## 4. 데이터 기준과 질문집

이번 오프라인 확인에 사용한 것은 프로젝트 상대 경로 `data/movies.json`이다. **현재 964개**이며 파일 SHA-256은 `cd0f231aea1097ee9310decdbdd186c1ecec89db91ee8f8174cb61435b1c1afd`다. 앱에 건수를 고정하는 제안이 아니다. 연도·상영 시간·평점·장르·제작 국가·줄거리는 현재 로딩 결과에 누락이 없고, 감독 목록이 빈 영화는 1개다. 연도는 1938~2026, 상영 시간은 74~242분, 평점은 4.432~8.728이다. 이는 제공 데이터의 시점별 필드 상태이며 현재 흥행·평가·상영 정보를 보증하지 않는다.

아래 건수는 새 검색의 결과가 아니다. 로더로 읽은 각 영화 필드에 독립적인 비교식을 적용해 센 **기대 적격 집합의 크기**다. 이후 테스트에서는 제품의 `_matches`나 파서 결과를 기대값 생성에 재사용하지 않고, 아래 조건을 직접 비교해 ID 집합을 만든다. 결과 개수 제한과 순위 때문에 화면 결과가 이 전체 집합과 같을 필요는 없다.

## 5. A/B 비교에서 같게 유지할 조건

| 항목 | 통제 방법 |
| --- | --- |
| 데이터와 저장 대응 | 위 파일 해시와 같은 카탈로그·같은 컬렉션 스냅샷, 안정 ID·텍스트 버전·본문 해시를 사용한다. 변경되면 이전 비교와 분리한다. |
| 임베딩 | 기존 GMS `text-embedding-3-small`, 1536차원, 같은 전처리 문장과 같은 질문 벡터다. 채팅 모델 호출은 필요 없다. |
| 질문 | O1~O3의 원문을 그대로 유지한다. 추가 질문은 위 표의 ID로 고정하며 변형하거나 특정 작품을 질문에 덧붙이지 않는다. |
| 검색 수와 순위 | 의미 `k=3`, 최종 최대 10개, 기존 키워드 산식·가중치·정규화 범위·동점 정렬을 그대로 둔다. `C`가 3개 미만인 경우에만 가능한 수로 줄인다. |
| 바꾸는 변수 | A는 전체 검색 후 조건 검증, B는 적격 ID 선필터 후 의미 검색이다. 파서 문법 변경, 임베딩 텍스트 변경, 재색인, Top-k 확대를 함께 수행하지 않는다. |
| 캐시 | 품질 비교는 양쪽 검색 캐시를 우회하거나 버전별로 분리한다. 기존 전체 검색 캐시를 B에 공급하지 않는다. 캐시 동작 검증은 별도 시나리오다. |
| 실행 환경 | 같은 Python·Chroma·머신·프로세스 조건을 기록한다. SDK 재시도 설정과 동시 실행 작업을 바꾸지 않는다. |

향후 실제 관련성 비교는 질문 하나의 벡터를 한 번만 얻어 A/B의 **로컬 컬렉션 질의**에 같이 사용하면 벡터 차이를 없애고 중복 호출을 줄일 수 있다. 이는 이후 구현에서 명시적으로 지원할 검증 경로이며 현재 `MetadataIndex.search`가 이미 벡터 재사용을 지원한다고 주장하지 않는다. 대표 3개와 명시 조건+의미가 함께 있는 소수 사례를 우선하고, 무조건 모든 질문마다 API를 호출하지 않는다. 동일 벡터 재사용 측정은 로컬 검색 비교이며 A/B 각각의 독립적인 전체 API 응답 시간으로 표시하지 않는다.

## 6. 관찰값·캐시·오프라인 검증 설계

질문별로 아래 값을 기록할 계획이다. 이번 문서에 새 품질 점수나 새 실행 시간은 없다.

- 파싱된 조건, 미지원 이유, `C`의 전체 개수와 정렬된 ID 해시, 누락 필드 때문에 판단하지 못한 개수.
- 의미 후보 ID·문서 ID·거리·순위, 최종 ID·순위·조건 근거, 각 최종 결과가 의미 후보인지 키워드 후보인지의 경로. `R − S`는 키워드 결합으로 허용되지만 그 작품을 의미 검색 결과라고 표시하면 안 된다.
- `S ⊆ C`, `R ⊆ C`, ID 중복 없음, `document_id = meta:{movie_id}`, 실제 레코드의 `movie_id` 대응. 후보와 최종 결과의 조건 위반·알 수 없는 ID·잘못된 문서 대응 건수는 모두 0이어야 한다. Top-k 때문에 `C − S`가 생기는 것은 정상이다.
- O1~O3의 기대 작품 순위와 Top-3 포함 여부를 A/B 모두에 남긴다. 조건 준수와 의미 관련성은 별도 결과다. 줄거리에 없는 상대성 이론·계층 갈등을 정답 필드로 만들어 정밀도나 정확도를 계산하지 않는다. 추가 의미 질의의 완전한 정답 집합이 없으면 순위와 실제 구절을 공개하고 종합 정확도는 미산출로 남긴다.
- 단계별 소요 시간은 조건 파싱·선필터·캐시·질문 임베딩·Chroma 조회·결합/검증으로 나눠 측정한다. 같은 조건의 반복 수를 기록하기 전에는 평균·백분위·속도 향상률을 쓰지 않는다. 캐시 적중과 비적중, 벡터 공유 로컬 비교와 실제 전체 흐름 시간을 분리한다.
- 질문 임베딩의 논리 호출 수·실제 시도 수·캐시 적중 여부·안전한 실패 분류를 구분한다. API 가격 근거 없이 비용을 확정하지 않는다. 이번 단계에서 키·환경변수 값·요청 헤더·원문 예외를 기록하지 않는다.

### 캐시 키와 무효화

현재 캐시 키에는 원문 질문·컬렉션명과 일부 카탈로그 필드만 들어간다. 국가·장르·출연·상영 시간·평점 조건을 추가 검증한 적격 집합과 캐시가 어긋나지 않도록, 업그레이드 캐시는 별도 버전으로 분리한다. 포함할 정보는 정규화된 조건(엄격 경계 플래그 포함), **정렬된 적격 영화 ID의 해시**, 의미 전처리 문장·버전, 의미 `k`, 실제 임베딩 모델·차원·컬렉션·텍스트 버전, 조건/순위 판정에 쓰는 전체 카탈로그 필드의 안정 해시다.

`C`의 해시만으로는 같은 ID의 줄거리·평점 등이 바뀐 경우를 놓치므로 카탈로그/텍스트 해시도 필요하다. 캐시를 읽은 후에도 반환 ID가 현재 `C`와 저장 ID 규칙에 맞는지 확인한다. 불일치 캐시는 성공으로 재사용하지 않는다. 실패·빈 의미 결과를 영구 성공 캐시로 만들지 않고 기존 성공 캐시의 유효 기간 계약을 유지한다. 이 캐시는 영화별 대화/출처 저장과 합치지 않는다.

오프라인 캐시 검증은 동일 질문의 재요청, 같은 의미 문장의 서로 다른 감독/국가 필터, 수치 포함/엄격 경계 변화, 정렬 순서만 바뀐 동일 ID 집합, 같은 ID의 조건 필드 변경, 구버전 캐시·범위 밖 ID 삽입을 구분한다. 색인 문서 수·본문·벡터는 이 검증으로 바뀌지 않아야 한다.

## 8. 이번 문서 작성에서 실제로 한 일과 하지 않은 일

실제로 한 일은 현재 `AGENTS.md`, `discovery.py`, `services.py`, `index.py`, 로더와 기존 검색 기록을 읽고, 설치 패키지 메타데이터 및 `Collection.query`/필터 검증 소스를 확인한 것이다. 프로젝트 가상환경 Python에서 `load_movies`로 로컬 JSON을 읽어 직접 필드 통계와 일부 기존 `parse_conditions` 해석을 출력했다. 테스트 러너·검색 서비스·임베딩 클라이언트를 실행하지 않았고, `.env`나 키를 읽지 않았다. Chroma 컬렉션을 열거나 조회·수정하지 않았다.
