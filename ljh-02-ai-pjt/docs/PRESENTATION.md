# Movie Lab 점검 자료와 보존 원고

**최신 사용자 지시: 발표는 없으며 발표 원고·슬라이드 작업은 종료했다.** 파일명과 아래 기존 원고는 기준본의 역사 자료로만 보존한다. 낭독 시간 측정·원고 확장·슬라이드 제작은 남은 작업이 아니다. 자기/동료 점검·제출 전 확인과 미확인 브라우저 절차는 계속 유지한다.

실행 방법은 [README](../README.md), 기능별 상태는 [통합 대조표](REQUIREMENTS.md)를 따른다. 이후 실제 구현 단계에서 두 질문·동일 탭 복원을 확인했다. 아래 원고는 역사 자료이고, 현재 점검 결과는 [최신 실제 보고서](../artifacts/review_upgrade/implementation_report.md)를 따른다.

## 기존 발표 원고 — 역사 자료, 작업 종료

안녕하세요. Movie Lab은 사용자가 영화를 찾고 선택한 뒤, 작품과 현실 배경에 관한 질문을 근거와 함께 확인하는 서비스입니다. 영화 메타데이터, 작품에 관한 설명, 현실의 사실, 사용자의 주장과 서비스의 판단을 구분하는 데 초점을 맞췄습니다.

사용자는 제목이나 자연어 조건으로 영화를 찾습니다. 결과에는 제목·연도·감독을 표시하고, 선택은 영화 ID로 처리합니다. 같은 제목의 영화도 구분하며, 확인할 수 없는 조건은 검증 불가로 안내합니다. 영화를 고른 다음 질문하면 필요한 자료를 준비하고, 근거를 검색해 답변과 실제 인용 구절을 보여줍니다.

핵심 설계는 다섯 가지입니다.

첫째, 영화 964편의 메타데이터와 외부 문서를 서로 다른 컬렉션에 저장했습니다. 선택 영화의 메타데이터는 항상 포함하고, 외부 문서는 그 영화 ID로 범위를 제한합니다.

둘째, 질문별 검색어·선별 결과와 문서별 본문 캐시를 분리했습니다. 같은 자료를 재사용하면서도 이전 질문으로 돌아갈 때 최신 본문을 과거 내용으로 되돌리지 않도록 했습니다. 실시간 문서와 제공 스냅샷의 수집 시점도 구분합니다.

셋째, LangGraph의 검색과 생성 노드를 연결했습니다. 답변은 이번에 확보한 근거로 작성하며, 질문 일부만 확인되면 확인 가능한 부분부터 답합니다.

넷째, 인용 검사를 두 단계로 나눴습니다. 코드는 번호·실제 원문 구절·문서 범위를 확인하고, 별도 모델 요청은 주장과 인용의 관계를 항목별로 검토합니다. 모델 검토를 통과해도 진실이 보장되는 것은 아닙니다.

다섯째, 대화와 출처를 영화별·답변별로 보존합니다. 같은 근거 번호라도 각 답변의 당시 출처에만 대응합니다. 새 답변이나 자료 갱신이 이전 답변의 출처를 덮어쓰지 않습니다.

실제로 확인한 첫 질문은 인터스텔라의 감독과 상영 시간입니다. 브라우저에서 크리스토퍼 놀란과 169분을 답했고, 같은 근거 1의 서로 다른 두 구절을 확인했습니다.

두 번째는 더 문 2023년 작품을 선택하고, 놀란이 감독했다는 주장과 달이 지구의 자연위성이라는 주장을 함께 물었습니다. 처음 브라우저 시연에서는 감독 정보가 문맥에 있어도 근거 부족으로 생성되는 문제가 있었습니다.

이를 보완해 명확한 감독 명제와 선택 영화의 실제 감독 행이 대응할 때만 검토용 제안을 만들도록 했습니다. 그 제안도 기존 인용 검사와 항목별 의미 검토를 거칩니다. 최신 실제 실행에서는 김용화라는 메타데이터에 따라 감독 주장은 근거와 상충, 자연위성 주장은 확인됨으로 수락됐습니다. 이 성공은 CLI로 한 질문을 재확인한 결과이며 새 브라우저 성공 기록은 아닙니다.

근거 부족은 자료로 확인하지 못했다는 뜻입니다. 검토 보류는 제안한 판단과 근거의 관계를 검토에서 수락하지 못했다는 뜻입니다. API 실패는 인증이나 서버 등 처리 단계의 오류입니다. 어느 경우도 곧바로 사용자의 주장이 거짓이라는 뜻은 아닙니다.

남은 한계도 있습니다. 감독 별칭·번역·복수 감독과 자유로운 모든 조건을 해결한 것은 아닙니다. 원래 브라우저의 A에서 B를 거쳐 A로 돌아오는 확인은 도구 세션 종료로 미확인입니다. 성공 사례와 실패·미확인을 구분한 기록을 제시하며, 앞으로 같은 응답이나 호출 수가 항상 재현된다고 보장하지 않습니다.

## 세 가지 상태를 구분해서 설명하기

| 상태 | 점검 때 확인할 의미 |
|---|---|
| 근거 부족 | 이번 근거로 해당 주장을 확인하지 못했다. 부재를 거짓의 증거로 삼지 않으며 관련 없는 인용을 강제하지 않는다. |
| 검토 보류 | 형식·인용·검토 응답·명제와 근거의 관계가 맞지 않아 제안을 수락하지 않았다. 통과한 다른 항목은 유지한다. |
| API 실패 | 요청 단계에서 처리 오류가 발생했다. 현재 확보한 저장 근거로 처리 가능한 부분과 실패한 단계를 구분하며, 오류를 사실 판정으로 바꾸지 않는다. |

## 구현 관련 질문과 설명 — 기존 참고 자료

**왜 컬렉션을 둘로 나눴나요?** 영화의 정체성을 나타내는 메타데이터와 질문에 필요한 외부 자료의 역할이 다릅니다. 메타데이터는 항상 넣고 외부 자료는 선택 영화로 제한합니다.

**인용이 있으면 답이 맞나요?** 번호·원문 포함 검사는 출처 대응을 확인합니다. 같은 모델의 의미 검토도 오판할 수 있으므로 실제 주장과 구절을 사람이 확인할 수 있게 제공합니다.

**감독 항목은 코드가 답을 정한 것 아닌가요?** 코드는 명확한 명제·영화 ID·카탈로그 표기·실제 감독 행이 대응할 때 제안만 만듭니다. 같은 묶음 검토가 관계와 이유를 수락해야 최종 판정에 남습니다. 검토 반려 시 감독만 보류하고 정상 배경 항목은 유지하는 [오프라인 계약 검사](../artifacts/review_director_field/offline_cases.json)도 있습니다. 고정 응답 검사는 모델 정확도 측정이 아닙니다.

**놀란과 놀런, 별칭도 같은 사람으로 처리하나요?** 부분 이름·번역·가까운 표기 차이는 보수적으로 기권합니다. 카탈로그 이름 목록은 완전한 인물 ID·별칭 사전이 아닙니다.

**영화를 바꿔도 대화가 유지되나요?** 영화별 저장과 출처 보존은 회귀로 확인했습니다. 원래 브라우저 A→B→A 시연은 미확인이므로 아래 수동 절차가 남아 있습니다. 완전 새로고침 이후의 영구 저장은 현재 범위가 아닙니다.

**모델·검색 품질이나 비용을 비교했나요?** 당시 원고 기준으로는 별도 모델 비교를 하지 않았습니다. 이후 이번 구현 단계에서 고정 근거·역할 분리로 후보 하나를 제한 비교했습니다. 일반 정확도·평균 성능·확정 비용은 제시하지 않습니다. 환경과 실행 세부는 [README](../README.md)와 [이번 보고서](../artifacts/review_upgrade/implementation_report.md)를 참고합니다.

## 이번 브라우저 결과와 같은 탭 A→B→A 재확인 절차

2026-10-22의 새 정상 앱 Chrome 탭 한 개에서 A 감독/169분과 두 구절, B 감독 상충/자연위성 확인됨, A 복원과 일반 rerun 무중복을 **실제로 확인**했다. [화면·결과](../artifacts/review_upgrade/browser/browser_results.json)와 [서버 이벤트](../artifacts/review_upgrade/browser/api_events.jsonl)를 근거로 한다. B의 질문 임베딩 502는 실패로 보존했고 로컬 근거로 답변했다. 사람의 동료 점검을 받은 결과는 아니다. 과거 중단된 세션은 당시 미확인으로 남긴다.

이 절차를 적었다고 검증이 완료된 것은 아니다. 정상 앱에서 같은 탭·같은 세션을 유지한다. 재생 서버나 저장 결과 주입으로 원래 시연의 성공을 대신하지 않는다. 새 세션에 답변이 없어서 질문을 보내면 추가 실제 호출이 발생할 수 있다.

- [ ] [실행 안내](../README.md)에 따라 정상 앱을 열고 인터스텔라 A를 선택한다. 완전 새로고침·탭 종료·서버 재시작을 하지 않는다.
- [ ] A의 기존 답변이 있으면 본문·메시지 개수·근거 번호·제목·원문 URL·구절을 기록한다. 기록이 없으면 직접 질문할 범위를 먼저 정하고, 한 번만 전송한 뒤 결과를 기록한다.
- [ ] 더 문(2023) B로 전환하고 A의 대화가 B에 나타나지 않는지 확인한다. B의 기존 기록은 별도로 확인하며, 기존 답변 표시만 확인할 때 같은 질문을 재전송하지 않는다.
- [ ] 사용자가 별도로 재확인할 범위가 정해졌을 때만 B에서 위 혼합 질문을 한 번 전송한다. 기대는 감독 **근거와 상충**·자연위성 **확인됨**이며, 실제 판정·구절·화면·오류를 그대로 기록한다. 이번 Codex의 실제 브라우저 확인과 사용자의 추가 수동 확인은 구분한다.
- [ ] 같은 탭에서 A로 돌아와 처음의 답변과 당시 출처가 모두 같은지 비교한다. 답변이 사라지거나 출처가 바뀌면 실패로 남긴다.
- [ ] 근거 펼침·모드 변경·일반 rerun 뒤 사용자/assistant 메시지가 중복되지 않는지 확인한다. 이 조작만으로 새 질문을 제출하지 않는다.
- [ ] 수행 시각·환경·통과/실패/미확인·화면 또는 로그 경로를 기록한 뒤에만 이 목록을 갱신한다.
