# ThRead

HTML, CSS, Bootstrap을 활용하여 구현한 도서 커뮤니티의 반응형 메인 페이지입니다. Navbar, Hero, 베스트셀러, AI 추천 소개, 장르별 도서 목록, 인기 쓰레드를 개별 파일에서 구현한 뒤 하나의 페이지로 통합했습니다.

## 사용 기술

- HTML5: 페이지 구조와 섹션 구성
- CSS3: 폰트, 색상, 이미지 크기, 간격 및 반응형 스타일
- Bootstrap 5.3.3: Navbar, Grid, Flex 유틸리티, Carousel, Card, Modal
- Git / GitLab: 기능별 브랜치 관리, 커밋 및 작업 내용 병합

F304~F306은 팀원이 구현한 내용을 공유받아 통합했습니다. 각자 작성한 파일의 구조와 스타일을 확인하면서 하나의 웹사이트로 연결했습니다.

현재 프로젝트는 정적 프런트엔드 구현입니다. AI 추천은 소개 UI이며 실제 추천 API와 연결하지 않았습니다. 검색·마이 페이지·쓰레드 페이지 번호의 실제 이동 기능과 서버 인증 기능은 포함하지 않습니다. F308의 로그아웃 버튼은 확인창을 닫는 동작이며, 실제 세션 삭제나 로그아웃 API는 연결하지 않았습니다.

## 실행 방법

별도 패키지 설치나 빌드 없이 `06-main.html`을 브라우저에서 열면 됩니다. Bootstrap을 CDN으로 불러오므로 인터넷 연결이 필요합니다.

Windows Git Bash에서는 프로젝트 폴더에서 다음 명령을 실행합니다.

```bash
start 06-main.html
```

개별 기능은 해당 HTML 파일을 열어 확인할 수 있습니다. [제출용 화면 캡처](screenshots/)도 함께 정리했습니다.

## 화면 확인 항목

- Navbar → Hero → 베스트셀러 → AI 추천 → 장르 목록 → 인기 쓰레드 순서로 표시되는지 확인합니다.
- 화면 너비 576px 미만에서 Navbar 토글과 Hero의 지정 위치 줄바꿈을 확인합니다.
- 베스트셀러가 4권씩 자동 전환되고, Next 버튼으로 마지막 슬라이드에서 처음으로 돌아오는지 확인합니다.
- 도서 표지가 150×220px이고 Next 버튼이 표지를 가리지 않는지 확인합니다.
- 장르 목록과 쓰레드 카드가 화면 크기에 따라 배치되는지 확인합니다.
- 로그아웃 메뉴를 눌렀을 때 Modal이 열리고 각 닫기 버튼이 동작하는지 확인합니다.

## 학습한 내용

### Bootstrap을 활용한 화면 구성

Navbar, Carousel, Card, Modal처럼 목적에 맞는 컴포넌트를 선택하고 필요한 HTML 구조와 속성을 연결하는 방법을 학습했습니다. Grid는 열의 비율을 나누는 데 사용하고, Flexbox는 요소의 방향·정렬·간격을 조정하는 데 사용하면서 두 방식의 차이를 익혔습니다.

### 반응형 레이아웃

화면 크기에 따라 메뉴를 접거나 카드의 열 수를 변경하는 방법을 학습했습니다. 특히 576px 미만과 576px 이하의 차이를 구분하고, 요구사항의 경계값에 맞는 Bootstrap 클래스와 미디어 쿼리를 적용해야 한다는 점을 배웠습니다.

### 협업과 기능 통합

기능별 파일과 브랜치를 나누어 작업한 뒤 병합하는 흐름을 경험했습니다. 개별 화면이 정상적으로 보여도 통합 과정에서 전역 CSS나 폰트 이름이 충돌할 수 있어, 공통 스타일과 섹션 전용 스타일을 구분하는 작업이 필요했습니다.

## 새로 배운 점

- CSS에서 쉼표는 대체 글꼴 목록을 연결하고, 세미콜론은 선언을 끝냅니다. 기호 하나가 달라도 의도한 스타일이 적용되지 않을 수 있습니다.
- `font-family`에 등록한 이름과 실제 폰트 파일명은 구분해야 합니다. 같은 파일을 사용하더라도 CSS에서 호출하는 이름이 다르면 폰트가 적용되지 않습니다.
- `data-bs-target`과 대상 요소의 `id`가 일치해야 토글, Carousel, Modal이 연결됩니다.
- Carousel은 첫 슬라이드에만 `active`를 지정하고, 모든 슬라이드를 같은 `carousel-inner` 안에 넣어야 합니다.
- CSS 중괄호 위치가 잘못되면 규칙이 다른 선택자 내부에 들어가 실제 요소와 매칭되지 않을 수 있습니다.
- 공통 폰트와 강조색을 한곳에서 관리하면 여러 섹션의 스타일을 일관되게 유지하기 쉽습니다.

## 어려웠던 부분과 해결 과정

### Next 버튼이 도서 표지를 가리거나 보이지 않던 문제

베스트셀러 Carousel에서 Next 버튼이 마지막 표지 위에 겹쳤고, 수정 과정에서는 화살표가 보이지 않기도 했습니다. CSS의 중괄호를 확인해 중첩된 규칙을 분리하고, Carousel 오른쪽 여백과 버튼 너비를 맞췄습니다. 흰 배경에서도 화살표가 보이도록 아이콘 색상도 조정했습니다.

### 슬라이드의 닫는 태그 위치

첫 번째 슬라이드 뒤에서 `carousel-inner`가 닫혀 나머지 슬라이드가 바깥에 배치된 문제가 있었습니다. 여는 태그와 닫는 태그를 확인하고, 세 슬라이드를 하나의 내부 영역에 담도록 구조를 정리했습니다. 화면이 일부 동작하는 것과 HTML 구조가 올바른 것은 따로 확인해야 한다는 점을 배웠습니다.

### 제목과 도서 목록 사이의 과도한 간격

컨테이너를 화면 전체 너비로 확장하면서 제목과 책 사이가 지나치게 벌어졌습니다. 섹션 너비에 상한을 두어 하나의 묶음으로 배치했습니다. 고정 이미지 크기와 사용할 수 있는 화면 너비를 함께 고려해야 했습니다.

### 통합 과정의 스타일 충돌

각 파일에서 사용한 전역 `.section-title`과 서로 다른 폰트 이름을 그대로 합치면 다른 섹션까지 영향을 받을 수 있었습니다. 공통 제목 스타일과 폰트 이름을 정리하고, 정렬이나 여백처럼 섹션마다 필요한 규칙은 해당 영역에 한정했습니다.

## 느낀점

처음에는 예시와 비슷한 화면을 만드는 데 집중했지만, 작업하면서 요구사항을 항목별로 확인하는 과정이 더 중요하다고 느꼈습니다. 제목 위치, 이미지 크기, 반응형 기준, 버튼 표시와 동작을 따로 점검하니 수정할 부분을 구체적으로 파악할 수 있었습니다.

작은 오타나 중괄호 하나가 화면 전체에 영향을 줄 수 있다는 점도 인상적이었습니다. 문제가 생겼을 때 스타일 값을 계속 바꾸기보다 HTML 구조와 CSS 적용 범위를 먼저 확인하는 습관이 필요하다는 것을 배웠습니다.

팀원과 만든 화면을 통합하면서 공통 규칙을 미리 정하는 것이 협업에 도움이 된다는 점을 느꼈습니다. 다음 작업에서는 폰트, 색상, 섹션 간격과 클래스 이름을 먼저 합의하고, 커밋에도 변경 내용과 이유를 명확히 남기고자 합니다. 이후에는 F309~F311의 추가 요구사항을 진행하며 레이아웃 개선과 상세 페이지 구현까지 확장할 계획입니다.
